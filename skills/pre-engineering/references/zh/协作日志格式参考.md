# 协作日志格式参考

## 日志格式规则

1. **只追加，不删除**：协作文档只在末尾追加新条目，不得删除或修改已有条目
2. **条目格式统一**：每条以 `## [时间] 角色 — 动作描述` 开头，末尾以 `状态：<状态码>` 结束
3. **条目间必须空行**：每个条目之间必须保留一个空行，确保格式一致可读
4. **状态声明必填且不可独立出现**：每个条目必须包含状态声明行作为条目的最后一行，格式精确为 `- 状态：<7个固定码之一>`。**状态声明绝不可脱离条目单独出现一行**——如 `状态：EXE_ING` 不可单独写一行，必须嵌在完整条目内；**状态码同样不可出现在标题行**（如 `## 时间 执行者 EXE_ING` 违规）——标题只写 `## [时间] 角色 — 动作描述`；**不得用叙述性措辞**（如"状态推进/下一步→REV_WAIT"）替代标准状态声明行
5. **结果摘要精炼**：内容行控制在 5 行以内（不含状态行）。日志条目是方向指引/变更摘要/审核结论，不是完整规格文档——验收标准、子任务列表、现状分析、代码详解等细节不在日志中，各角色自主推导。**5行是上限不是放行**：即使不超行，把禁止内容塞进单行（如方案行夹现状诊断、理由行铺三维度、追加「改进建议」槽位）同样违规——行数合规不等于内容合规
6. **状态码标准化**：只能使用7个固定状态码，不可自创状态码
7. **时间必须从系统获取**：写入日志条目时，必须先执行 `date +"%Y-%m-%d %H:%M"` 获取系统当前时间，将命令输出直接用于条目时间字段——不可凭记忆或上下文推算填写

## 日志操作硬性规则（防止日志损坏）

1. **每轮必读实际文件**：每次行动前必须读取协作日志的完整文件内容获取最新状态码——不得凭记忆或上下文推断，不得假设"上次看到的状态仍然有效"
2. **Shell追加写入**：协作日志的写入必须通过shell追加命令完成（`cat >> 日志文件路径 <<'EOF'` ... `EOF`），禁止使用Write工具重写整个文件，禁止使用Edit工具修改已有行。shell追加操作天然只能写入文件末尾，不可能修改已有内容。注意：结束标记 `EOF` 必须顶格书写（行首无空格、无缩进），否则 shell 不识别为结束符，命令将挂起等待输入直至超时
3. **状态验证后才行动**：确认日志末尾的状态码与本角色行动条件匹配后才可行动。状态不匹配则跳过，不做任何写入

## 各角色条目格式模板

规划者：
```markdown
## [时间] 规划者 — <动作描述>
- 需求：[需求名称，1行]
- 方案：[方案方向要点，1-2行]
- 交付：[预期产出，1行]
- 状态：<状态码>
```

执行者：
```markdown
## [时间] 执行者 — <动作描述>
- 产出：[文件路径，1行]
- 变更：[关键变更要点，2-3行]
- 状态：<状态码>
```

审核者：
```markdown
## [时间] 审核者 — <动作描述>
- 结论：[通过/驳回，1行]
- 理由：[核心要点，1-2行]
- 状态：<状态码>
```
```

## 监督者控制条目

监督者（Supervisor）是协作日志的合法作者之一，仅写控制类条目（不写项目工作内容）。控制条目同样遵循只追加、shell `cat >>` 写入、时间用 `date +"%Y-%m-%d %H:%M"` 实取，并以 `状态：<状态码>` 结尾（修复/熔断时为当前未变状态码；停摆时为 `DONE`）：

- 修复：`## [时间] 监督者 — 修复：<角色> <动作与原因>`，`状态：<当前状态码>`
- 熔断：`## [时间] 监督者 — <角色> BLOCKED：<原因>`，`状态：<当前状态码>`
- 停摆：`## [时间] 监督者 — 项目 DONE，监督者停摆`，`状态：DONE`

诊断过程不写入日志。

## 状态声明行格式

`状态：<状态码>` — 状态码为智能体判断执行条件的唯一依据，必须精确匹配7个固定状态码之一。

```markdown

## [2026-05-11 10:00] 人工 — 项目启动
- 初始化项目，请规划者开始首次规划
- 状态：PLN_WAIT

## [2026-05-11 14:00] 规划者 — 开始规划
- 目标：实现用户登录功能
- 状态：PLN_ING

## [2026-05-11 14:12] 规划者 — 需求规划完成
- 需求：实现用户登录功能
- 方案要点：JWT + bcrypt + React 表单库
- 状态：REV_WAIT

## [2026-05-11 14:25] 审核者 — 需求审核通过
- 需求合理，方案可行，与现有代码兼容
- 状态：EXE_WAIT

## [2026-05-11 14:40] 执行者 — T1 执行完成
- 产出文件：src/components/Login/index.tsx
- 关键变更：新增登录表单组件，含表单校验与提交逻辑
- 状态：REV_WAIT

## [2026-05-11 15:00] 审核者 — 产出审核驳回
- 驳回原因：登录组件缺少 loading 状态和错误提示处理
- 状态：EXE_WAIT

## [2026-05-11 15:10] 执行者 — T1 重新执行完成
- 产出文件：src/components/Login/index.tsx（已补充 loading 和错误提示）
- 状态：REV_WAIT

## [2026-05-11 15:40] 审核者 — 产出审核通过
- 状态：PLN_WAIT

## [2026-05-11 16:10] 规划者 — 需求规划完成
- 需求：实现用户注册功能
- 状态：REV_WAIT

...（循环直至项目目标中所有功能交付）

## [2026-05-11 17:35] 规划者 — 无新需求声明
- 项目目标中已无新的需求
- 状态：REV_WAIT

## [2026-05-11 17:45] 审核者 — 确认项目完成
- 确认项目目标已全部交付
- 状态：DONE
