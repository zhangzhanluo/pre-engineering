# 协作日志格式参考

## 日志格式规则

1. **只追加，不删除**：协作文档只在末尾追加新条目，不得删除或修改已有条目
2. **条目格式统一**：每条以 `## [时间] 角色 — 动作描述` 开头，末尾以 `状态：<状态码>` 结束
3. **条目间必须空行**：每个条目之间必须保留一个空行，确保格式一致可读
4. **状态声明必填且不可独立出现**：每个条目必须包含状态声明行作为条目的最后一行。**状态声明绝不可脱离条目单独出现一行**——如 `状态：EXE_ING` 不可单独写一行，必须嵌在完整条目内
5. **结果摘要精炼**：内容行控制在 5 行以内（不含状态行）
6. **状态码标准化**：只能使用7个固定状态码，不可自创状态码
7. **时间必须从系统获取**：写入日志条目时，必须先执行 `date +"%Y-%m-%d %H:%M"` 获取系统当前时间，不可凭记忆或推算填写

## 条目格式模板

```markdown
## [时间] 角色 — <动作描述>
- 内容行1
- 内容行2
- 状态：<状态码>
```

## 状态声明行格式

`状态：<状态码>` — 状态码为智能体判断执行条件的唯一依据，必须精确匹配7个固定状态码之一。

## 完整示例日志

```markdown
# 协作日志

## [2026-05-11 10:00] 人工 — 项目启动
- 初始化项目，请规划者开始首次规划
- 状态：PLN_WAIT

## [2026-05-11 14:00] 规划者 — 开始规划
- 目标：实现用户登录功能
- 状态：PLN_ING

## [2026-05-11 14:12] 规划者 — 需求规划完成
- 需求：实现用户登录功能
- 方案要点：JWT + bcrypt + React 表单库
- 状态：REV_WAIT

## [2026-05-11 14:25] 审核者 — 需求审核通过
- 需求合理，方案可行，与现有代码兼容
- 状态：EXE_WAIT

## [2026-05-11 14:40] 执行者 — T1 执行完成
- 产出文件：src/components/Login/index.tsx
- 关键变更：新增登录表单组件，含表单校验与提交逻辑
- 状态：REV_WAIT

## [2026-05-11 15:00] 审核者 — 产出审核驳回
- 驳回原因：登录组件缺少 loading 状态和错误提示处理
- 状态：EXE_WAIT

## [2026-05-11 15:10] 执行者 — T1 重新执行完成
- 产出文件：src/components/Login/index.tsx（已补充 loading 和错误提示）
- 状态：REV_WAIT

## [2026-05-11 15:40] 审核者 — 产出审核通过
- 状态：PLN_WAIT

## [2026-05-11 16:10] 规划者 — 需求规划完成
- 需求：实现用户注册功能
- 状态：REV_WAIT

...（循环直至项目目标中所有功能交付）

## [2026-05-11 17:35] 规划者 — 无新需求声明
- 项目目标中已无新的需求
- 状态：REV_WAIT

## [2026-05-11 17:45] 审核者 — 确认项目完成
- 确认项目目标已全部交付
- 状态：DONE
```
